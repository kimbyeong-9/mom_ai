# 해결방안탐색서 — LifeFlow AI (Mom AI)

## 목적

문제정의서에서 도출된 사용자 문제를 Loop 단위로 분해하고  
각 Loop의 전환율을 높이기 위한 아이디어를 탐색·분석한다.

---

## Planning Loop 개선안

### 문제

- 사용자가 목표를 입력했지만 AI Planning 단계로 넘어가지 않음 (GP1 낮음)
- Planning 결과를 끝까지 확인하지 않음 (GP2 낮음)

### 개선 아이디어

#### A. 단계별 목표 입력 마법사 (구조화된 질문 흐름)

- (2026-07 개정) 단일 자유 텍스트 입력 대신, 국가/지역 → 직군 → 경력 → 목표 시점 →
  비자·체류 자격 → 언어 수준 → 근무 형태 순의 고정된 8단계 질문 흐름(`/start`)으로 구현
- 자유 대화형 챗봇이 아니라 정해진 순서의 구조화된 질문인 이유: 마지막 스텝 제출 시점이
  명확해야 `goal_input_submitted`(GP1 분자) 측정이 가능하기 때문 — 열린 대화형은 "입력 완료"
  시점이 모호해져 지표 자체가 흔들린다
- 장점: 탐색 피로 제거, 개인화된 입력을 지표 훼손 없이 확보
- 단점: 자유 텍스트 한 줄보다 완료까지 시간이 걸림 → 진행률 표시·이어하기(resume) 기능으로 보완

#### B. 상황 맞춤형 준비 절차 제공

- A의 8단계 답변(국가, 직군, 경력, 비자 상태, 근무 형태 등)에 따라 다른 절차를 제공
- 장점: 개인화로 관련성 높아짐
- 단점: 초기엔 온보딩 1단계로 제한하려 했으나, 좁힌 2개 버티컬은 이 정도 깊이의 입력을
  받을 만큼 의도가 명확한 사용자층이라 판단해 다단계 입력으로 전환 (결정로그 01 참고)

#### C. 행동 연결 정보 제공 — 지금 가장 약한 고리

- 각 절차에 실제 행동(링크, 서류, 기관)을 직접 연결
- 장점: Planning → 행동 전환율 개선
- 단점: 정보 유지·갱신 비용 발생 — (2026-07) 이 비용을 안 치르고 LLM에게 "확신할 때만 링크를
  채워라"고 떠넘긴 결과, 대부분 링크 없는 텍스트만 나오는 상태. 두 가지 방향을 검토 중:
  1) 버티컬별 실제 데이터(비자 요건, 채용 플랫폼, 서류 목록)를 직접 큐레이션
  2) LLM에 실제 검색 그라운딩(웹 검색 도구) 연결
  아직 결정 안 됨 — 다음 작업 우선순위 후보

### 관찰 포인트

- Goal Input 완료율
- Planning 결과 스크롤 깊이
- Planning 결과 체류 시간

## Save Loop 개선안

### 문제

- Planning 결과를 봤지만 저장하지 않음 (SP1 낮음)
- 저장했지만 다시 진입하지 않음 (RP1 낮음)
- 동일 Goal을 다시 탐색함 (ReSearch_R 높음)

### 개선 아이디어

#### A. 결과 자산화 구조

- Planning 결과를 "내 플랜"으로 저장할 수 있는 명확한 UI 제공
- 저장된 플랜은 언제든 재접근 가능
- 장점: 저장 행동 자연스럽게 유도
- 단점: 저장 공간 관리 UX 필요

#### B. 저장 행동 유도 구조

- Planning 결과 확인 후 저장 CTA(Call To Action)를 즉시 노출
- "이 플랜을 저장하면 나중에 다시 볼 수 있어요" 맥락 메시지
- 장점: SP1 직접 개선
- 단점: 너무 이른 CTA는 사용자 경험 저하 가능

#### C. 재진입(Revisited) 유도 구조

- 저장된 플랜에 대한 알림, 리마인더 제공
- "저번에 준비하던 ○○ 계속 진행할까요?" 형태의 재진입 트리거
- 장점: RP1 개선, ReSearch_R 감소
- 단점: 알림 피로 유발 가능

### 관찰 포인트

- Planning 결과 → 저장 버튼 클릭률
- 저장된 플랜 재방문 빈도
- 동일 Goal 재탐색 비율

## Automation Loop 개선안

### 문제

- 저장된 플랜에서 자동화로 연결되지 않음 (AP1 낮음)
- 자동화를 연결했지만 실행되지 않음 (AP2 낮음)

### 개선 아이디어

#### A. 자동화 연결 추천 구조

- 저장된 플랜의 각 단계에서 자동화 가능한 항목을 AI가 탐지·추천
- "이 단계는 자동화할 수 있어요" 인라인 추천
- 장점: 자동화 인지율 향상
- 단점: 자동화 가능 항목 판단 정확도에 의존

#### B. 원클릭 실행 기능 → 지속 실행 구조로 재정의 (2026-07 개정)

- 기존: 연결된 자동화를 한 번 클릭하면 즉시 실행되고 끝나는 1회성 구조
- 문제: 지금 백엔드(`automations.service.ts`)는 실제로 외부 세계와 상호작용하지 않는
  가짜 로직(정규식으로 서류명 추출, 계산만 하고 안 보내는 알림 날짜)이라 "연결했더니 진짜로
  뭔가 일어난다"는 느낌이 없다
- 개정 방향: **n8n을 실제 실행 엔진으로 연결** — 백엔드는 자동화의 상태/이벤트만 소유하고,
  n8n이 스케줄 트리거로 실제 채용 플랫폼/비자 정보 소스를 폴링해서 웹훅으로 콜백하는 구조.
  1회성 실행이 아니라 "연결해두면 계속 대신 찾아봐주는" 자동화로 전환
- 우선순위: ① 채용/원격구인 모니터링 (기존 `notification` 타입 재정의) → ② 비자·체류 마감일
  리마인더 (기존 `extractDeadlineDate` 로직을 n8n 스케줄로 실제화)
- 장점: AP2뿐 아니라 자동화 자체의 체감 가치가 완전히 달라짐 (1회성 실행 → 지속적 대행)
- 단점: n8n 인스턴스 운영/보안 관리 필요, 실행 로직 일부가 코드 밖(비주얼 워크플로우)으로 이동

### 관찰 포인트

- 자동화 추천 클릭률
- 자동화 연결 완료율
- 자동화 실행 성공률
