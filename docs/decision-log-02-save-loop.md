# 결정로그 02 — Save Loop 전환율 개선

## 주제

Save Loop 전환율 개선

## 관련 지표

| 지표 | 목표 방향 |
|------|-----------|
| SP1 | Result Viewed → Save 전환율 ↑ |
| RP1 | Save → Revisited 전환율 ↑ |
| Save_LCP | Save Loop 완료율 ↑ |
| ReSearch_R | 동일 Goal 재탐색 비율 ↓ |

---

## 결정 사항

### 1. 결과 자산화 구조

**결정**: Planning 결과를 "내 플랜"으로 저장할 수 있는 구조를 제공한다.  
저장된 플랜은 Saved 페이지에서 목록 형태로 관리된다.

**근거**:
- 사용자가 Planning 결과를 소비성 정보가 아닌 자산으로 인식하게 만들어야  
  저장 행동(SP1)이 발생한다
- 저장된 플랜 목록은 재진입(RP1) 경로가 된다

**제약**:
- 저장은 로그인 사용자만 가능하다 (비로그인 → 저장 시도 → 로그인 유도)

---

### 2. 저장 행동 유도 구조

**결정**: Planning 결과 하단에 "플랜 저장하기" CTA를 고정 노출한다.  
저장 전 맥락 메시지("저장하면 나중에 다시 볼 수 있어요")를 표시한다.

**근거**:
- Planning 결과를 확인한 직후가 저장 의도가 가장 높은 시점이다
- 명확한 CTA 없이는 저장 행동이 발생하지 않는다

**제약**:
- CTA는 결과 스크롤 25% 이후부터 노출하여 결과 확인 전 방해를 최소화한다

---

### 3. 재진입(Revisited) 유도 구조

**결정**: 저장된 플랜 목록(Saved 페이지)에서 각 플랜의 진행 상태를 시각적으로 표시한다.  
"저번에 여기까지 했어요" 형태의 진행률 표시를 제공한다.

**근거**:
- 저장 후 재진입하지 않으면 RP1이 낮아지고 ReSearch_R이 높아진다
- 진행 상태 시각화는 재진입 동기를 부여한다

**제약**:
- 초기 MVP에서는 진행률을 수동 체크로 구현하고, 이후 자동 추적으로 개선한다

---

## 기능 구현 우선순위

1. 저장 버튼 컴포넌트 (Planning Result 하단)
2. 저장 API 연동
3. Saved 페이지 — 저장된 플랜 목록
4. 플랜 카드 컴포넌트 (제목, 저장일, 진행률)

---

## 검증 방법

| 지표 | 측정 방법 |
|------|-----------|
| SP1 | 저장 버튼 클릭 이벤트 / Result Viewed 이벤트 |
| RP1 | Saved 페이지 진입 이벤트 / 저장 이벤트 |
| Save_LCP | SP1 기준 |
| ReSearch_R | 동일 Goal 재입력 횟수 추적 |
